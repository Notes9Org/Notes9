## The problem in one page

Two findings drive everything below, both verified in source rather than inferred.

**There are three seams, and two of them bypass the HTTP contract.** The documented one
is HTTP Notes9→Catalyst. The second is a `service_role` Postgres connection held by the
AI service that reads 26 tables with RLS bypassed, across three separate access paths
(PostgREST, a raw psycopg2 pool for pgvector, and httpx to Storage). The third is the
`chunk_jobs` table used as a queue, where Postgres *is* the integration and the two
services never speak. So Notes9 sends `{kind, id}` over HTTP and the AI side performs an
unrestricted row read: **ids cross HTTP, rows cross the database.** Any design that only
types the HTTP payload leaves most of the real data flow ungoverned.

**There are two determinism architectures, not one.** Data Analysis is *structural* and
fail-closed: `lib/data-analysis/ai/spec-author.ts:18-19` states that no statistic may
originate from the model and that this is "enforced by construction: the tool schema has
no field capable of carrying one." Every other AI surface is a *post-hoc retrofit* and
every guard on it is fail-open — the citation entailment judge defaults to `shadow` and
mutates nothing in production, span grounding degrades on timeout, and
`core/citations.py:1046` carries the comment "fail-open: verification never breaks
compose." There is no code path anywhere that refuses to show a main-agent answer because
a number in it is unattributable.

Those two findings have one shared cause and therefore one shared fix. The Data Analysis
path is safe because **its contract has no field that can carry an unattributed fact.**
Safety is a property of the schema, not of an inspector that runs afterwards. So "one
typed contract per seam" and "Law 2 everywhere" are not two workstreams. They are the
same workstream seen from two ends.

## The central move

Generalise the mechanism this codebase has already proven twice and generalised zero
times.

It exists at `core/citations.py:32-39`, where a citation token is minted by deterministic
code at tool-emit time and the model can only *copy* it. That is the single structural
guard on the entire fail-open path, and it works. It exists again at
`lib/data-analysis/spec/mutation-schema.ts:216`, where the prompt contract is generated by
walking the validator, so prompt and validator cannot drift.

**Every fact a user can see is minted by its deterministic producer and carries a token.
The model may reference a token. The model may never type a digit.**

A producer is anything that computes or retrieves: the Pyodide statistics engine, a SQL
result, a row read, a retrieval hit, a curve fit. Each emits into a per-turn **fact
ledger**:

```
FactToken   = "⟦f" <n> "⟧"
Fact        = { token, value, rendered, unit?, producer, producer_version, source_ref }
```

The model receives the ledger as context and writes prose containing tokens. A
deterministic composer substitutes `token → rendered` as the final step before the user
sees anything. Because substitution is the last hop and the model never typed the digits,
the number on screen provably came from the producer.

This is what resolves the apparent conflict in the two rules the product now holds.
Quoting an engine value is *attribution* and is allowed, because the model emits a token
rather than a number. Computing a value is *fabrication* and is refused, because a raw
numeric literal that is not a token fails the default-deny check that
`spec-author.ts:408-438` already implements. Prohibition is what applies exactly where
attribution is impossible. See [[analysis/adr-010-attested-values-the-model-references-facts-it-never-mints-them]].

Three rules hold this together, and each kills a class of defect found in the review.

**One client per seam.** Today ~12 Notes9 call sites reach Catalyst and only four use
`lib/catalyst-client.ts`; the streaming routes hand-roll `fetch` because `callCatalyst` is
JSON-only (it always calls `res.json()` at `catalyst-client.ts:174`). Two callers bypass
the URL resolver entirely and read `CHAT_API_URL` directly, so setting only `CATALYST_URL`
silently breaks them. The seam client must support both JSON and SSE so there is no reason
left to hand-roll.

**One authorisation implementation.** Row authorisation currently exists three times
(Postgres RLS, Python membership at `core/retriever.py:196-212`, and a `created_by`-only
filter at `infra/rag.py:210-250`) and the AI repo's own `ADR-0002` records that two of them
already disagree, still open. See
[[analysis/adr-012-a-single-authorized-reader-owns-the-service-role-path]].

**One place facts are minted.** See ADR-010.

## Interfaces

This section is the contract between parallel worktree agents who cannot read each other's
code. `CLAUDE.md` records that weak interfaces were the Tier 0 root cause here and surfaced
as rail-over-spec in four disguises. Everything below is normative and complete.

### I1 — Contract package layout (new, shared)

Single source of truth, one directory, vendored into both repos:

```
contracts/v1/
  seam.request.schema.json        # envelope common to every seam call
  seam.response.schema.json       # discriminated on `outcome`
  sse.events.schema.json          # all 20 event types, one vocabulary
  facts.schema.json               # Fact / FactToken (ADR-010)
  limits.json                     # every cap, ONE number each
  CONTRACT_HASH                   # sha256 over the sorted concatenation of the above
```

Vendored to `Notes9/lib/seam/contracts/v1/` and `AI/catalyst/contracts/v1/`. Both repos
carry a test asserting their local `CONTRACT_HASH` equals the hash recomputed from their
own copies, and CI in both repos fails on mismatch. This generalises the one joint that
already works: `spec-patch-proposal.contract-fixture.json` is byte-identical across repos
and tested on both sides including key order. Its only weakness is that nothing compares
the two files, so a one-sided edit leaves both suites green. `CONTRACT_HASH` closes exactly
that. See [[analysis/adr-011-one-contract-per-seam-enforced-by-a-parity-fixture]].

### I2 — Seam envelope

Request, every seam, every route:

```jsonc
{
  "contract_version": "1",          // REQUIRED. major only. see ADR-013
  "seam": "agent" | "analysis-spec" | "literature" | "artifact",
  "thread": { "id": string, "turn": integer },   // see ADR-015
  "payload": { ... }                // seam-specific, schema per seam
}
```

Response, every seam, every route, **always carrying the discriminant**:

```jsonc
{ "contract_version": "1",
  "outcome": "ok" | "refused" | "clarify" | "bad-request"
           | "unauthorized" | "unavailable" | "contract-mismatch",
  "payload": { ... },               // present iff outcome === "ok"
  "reason": string,                 // present iff outcome !== "ok"
  "facts": Fact[] }                 // see I4; MAY be empty, MUST be present
```

`outcome` is present on **every** branch including success. Today the spec-author success
case ships with no discriminant at all and the client manufactures one, and one error case
(`refused`) returns HTTP 200 while its siblings return 4xx. Both are removed by this shape.

HTTP status mirrors `outcome` exactly: `ok`→200, `clarify`→200, `refused`→200,
`bad-request`→400, `unauthorized`→401, `contract-mismatch`→409, `unavailable`→503.
`refused` and `clarify` are 200 because they are *answers*, not failures — that part of
today's behaviour is correct and is preserved deliberately.

### I3 — SSE, one vocabulary

`sse.events.schema.json` is the union of all 20 event types currently in
`AI/catalyst/core/sse_schema.py:258-279`. Two changes are normative:

- The literature protocol (`started`/`step`/`result`/`done`) is **retired** and re-expressed
  in the core vocabulary, so one parser serves every stream. It is currently a second,
  incompatible vocabulary and a client cannot share a parser between the two.
- `text_reset` stays in the vocabulary and must be documented. A client that does not
  handle it renders corrupted text, and it is absent from `API_DOCUMENTATION.md` today,
  which documents 5 of the 20 events.

Unknown event names MUST be ignored by clients (forward compatibility). Unknown *fields*
within a known event MUST be preserved, never dropped.

### I4 — Fact ledger

```jsonc
// Fact
{ "token": "⟦f3⟧",
  "rendered": "0.0079",             // EXACT string the user will see
  "value": 0.0079,                  // machine value, for callers that recompute
  "unit": "p",                      // optional
  "producer": "notes9-stats",       // WHO computed it
  "producer_version": "1.2.0",      // engine/tool version
  "source_ref": "spec:9f3a…|row:…"  // what it was computed from
}
```

Rules, normative:

1. A producer MUST mint a token for every value it intends the user to see.
2. The model MUST NOT emit a numeric literal outside a token, except: a value that is
   part of a name (`CD8`, `p53`), a bare integer below 100, or a 4-digit year. This is the
   default-deny rule already implemented at `spec-author.ts:392-438`, lifted verbatim.
3. The composer substitutes `token → rendered` as the **last** step before display.
4. A token with no matching ledger entry is a hard error; the surrounding sentence is
   removed and the removal is disclosed, following `sanitiseRationale` at `:453-470`,
   which already says something was removed rather than silently editing.
5. Withholding MUST be strictly safer than not withholding. This is not a style note: at
   `spec-author.ts:480-484` nulling a refused clarification *enabled* the Execute button.
   Any new guard is reviewed against this rule specifically.

### I5 — AuthorizedReader (AI repo)

The **only** module permitted to import the Supabase service credential or the psycopg2
pool. Enforced by the existing package-layering test (`tests/test_package_layering.py`
already proves this pattern for the LLM gateway).

```python
class AuthorizedReader:
    def __init__(self, user_id: str, org_id: str | None) -> None: ...
    def rows(self, table: str, ids: list[str]) -> list[dict]: ...
    def vector_search(self, embedding: list[float], k: int) -> list[Chunk]: ...
    def scope_predicate(self, table: str) -> str: ...   # the ONE scope rule, as SQL
```

`scope_predicate` returns the same SQL the RLS policy uses. A conformance test runs a
matrix of (owner, collaborator, org peer, outsider) × (own row, project row, org row,
foreign row) through both RLS and `scope_predicate` and asserts identical row sets. That
test is what makes "three implementations" become one. See ADR-012.

### I6 — Limits, one number each

`contracts/v1/limits.json` is the sole definition. Both repos read it; neither declares a
local constant. Today four caps disagree — query chars 100,000 against 10,000, attachments
50 against 5, history 400 against 100, message chars 200,000 against 100,000 — and the
disagreement is masked because `LIMITS_MODE` defaults to `shadow` on both sides, so Notes9
logs and does not block and the effective ceiling is Catalyst's Pydantic, surfaced to the
user as a raw 422.

Resolution rule: **the smaller of the two current values wins**, because that is the value
already in force in production. Raising a cap is a separate, deliberate change.

Note the compound bound that must be expressed and is not today: `query` is capped at
10,000 characters while `history[].content` allows 100,000 across 32 entries, giving a
~3.2 MB effective body through the history field. `limits.json` carries a
`total_request_bytes` cap that binds the whole envelope.

### I7 — Thread identity

```jsonc
"thread": { "id": string, "turn": integer }
```

`id` is the surface's own natural key: the analysis tab id for Data Analysis, the chat
session id for Catalyst. No new identifier is minted. `turn` increments per user message.
History rides `payload.context.turns`, **never** the prompt string — putting turns in
`prompt` competes with the 4,000-character bound that ADR-004 enforces and starves the
repair round that bound exists to protect. See ADR-015.

## Failure modes

| Mode | Guaranteed behaviour | Owned by |
|---|---|---|
| **Volume** 10× turns/sec on one thread | Per-thread turn serialisation; a second in-flight turn for the same `thread.id` is rejected `409 contract-mismatch` rather than interleaved | seam client (I2) |
| **Volume** 10× rows behind one tag id | `AuthorizedReader.rows` is bounded by `limits.json:max_rows_per_fetch`; over-limit truncates and mints a `truncated` fact so the model can say so | AuthorizedReader (I5) |
| **Size** largest realistic payload | Rejected at the seam client *before* the network call with the typed `bad-request`, using the shared `limits.json`. One byte past → same path, never a raw upstream 422 | seam client + I6 |
| **Size** answer longer than the grounding cap | `MAX_GROUNDING_PAIRS=60` currently drops span citations off the tail silently. Facts beyond the cap render as doc-level attribution and a `degraded` health flag is set; never silent | composer (I4) |
| **Shape** unknown field in request | Accepted and preserved if the major version matches (additive rule), never silently dropped. Replaces today's allowlist proxy, which has silently dropped four fields already | ADR-013 |
| **Shape** unknown SSE event | Ignored by the client, stream continues | I3 |
| **Shape** model emits a bare numeric literal | Default-deny: sentence removed, removal disclosed | I4 rule 2/4 |
| **Shape** model emits an unknown token | Hard error, sentence removed, disclosed | I4 rule 4 |
| **Cost/latency** model call at real usage | Gateway default `temperature=0.0` makes identical inputs cacheable; the fact ledger is the cache key alongside prompt hash | ADR-014 |
| **Cost/latency** timeout mid-flight | Cancellation is **cooperative everywhere** today — an in-flight LLM call always runs to completion, so every SLO must budget one full model call past the deadline. Documented, not fixed here | out of scope, named |
| **Partial failure** producer succeeds, model fails | Facts are already minted and persisted; the turn is retryable without recomputing | fact ledger |
| **Partial failure** model succeeds, composer finds a dangling token | Sentence removed, rest of the answer stands, disclosure appended | I4 rule 4 |
| **Partial failure** one of two DB writes commits | `chunk_jobs` claim is already atomic with 900 s stale recovery; unchanged | S3, existing |
| **Partial failure** retry arrives twice | `thread.id` + `turn` is the idempotency key; a repeated `turn` returns the stored result rather than recomputing | I7 |
| **Boundaries** another tenant's row | `AuthorizedReader` is the single gate; conformance test asserts parity with RLS across the four-role matrix | I5 |
| **Boundaries** empty ledger | `facts: []` is valid; the model simply has nothing to reference and any numeric literal is denied | I4 |
| **Version skew** old client, new server | `contract_version` major mismatch → `409 contract-mismatch` with the supported range, never a silent degrade | ADR-013 |
| **Version skew** new client, old server | Same 409, detected client-side from the response envelope | ADR-013 |
| **Version skew** rows written before the migration | Fact ledger is additive and per-turn; nothing is read back from before it existed | ADR-010 |
| **Version skew** one repo deploys first | Additive-within-major means either order is safe. `CONTRACT_HASH` mismatch fails CI before either can ship a breaking change | ADR-011 |
| **Environment skew** optional dependency changes behaviour | `rapidfuzz` is optional today and silently switches the grounding metric (Levenshtein vs difflib) against the same 0.55 threshold, so grounding differs by environment. Pin it as a hard dependency | ADR-014 |
| **Environment skew** two instances disagree | The citation verdict cache is process-local, so two instances behind a load balancer can legitimately disagree about whether a span supports a claim. Key the cache on the fact token and make it shared or disabled, never process-local | ADR-014 |

## Rollout

- **Migration order.** No schema migration in wave 1. The `contracts/` package and CI land
  first, in both repos, before any behaviour change. Waves 3–4 touch no DDL either; the
  `AuthorizedReader` conformance test reads existing RLS policies rather than altering them.
- **Backward-compat window.** One full major version. `contract_version: "1"` servers must
  accept clients that omit the field entirely, treating absent as `"1"`, for the duration of
  wave 1 and 2. That is what lets the two repos deploy in either order.
- **Flag.** `SEAM_CONTRACT_ENFORCE` (`shadow` | `enforce`), defaulting to `shadow`, mirroring
  the existing `LIMITS_MODE` convention. **Note the trap this inherits:** `LIMITS_MODE`
  defaulting to `shadow` on both sides is precisely why four cap mismatches survived
  unnoticed. So the flag ships with a dashboard on shadow-mode violations and a dated
  decision to flip to `enforce`, not an open-ended shadow period.
- **Rollback.** Code-only in every wave, so `git revert` is the primitive and is safe. There
  is no down-migration to write because there is no migration. If a later wave adds one,
  that wave writes its own down path.
- **The one signal that says it broke.** Count of responses with
  `outcome: "contract-mismatch"`, by seam, over five minutes. Zero is the steady state.
  Non-zero means the two repos disagree about the contract and it is the first thing to
  check at 3am. Second signal: count of composer token-substitution failures, which is the
  Law 2 guard firing.

## Preconditions, not design items

**A live `service_role` credential is committed to git.** `AI/worker/.env.example` is
tracked and pushed to `origin/main` of the private repo `Notes9Org/AI-service`, containing a
decodable JWT for production project `rutcjpugsrfoobsrufnn` with `role=service_role` and
expiry in 2035. Rotation is the operator's action and is **not** part of any wave below.
This architecture assumes rotation has happened, and ADR-012 specifies how a service
credential is held afterwards: injected at runtime, never in a file tracked by git, held by
exactly one module, and absent from `.env.example` which by definition is committed.

**Two schema baselines disagree.** `Notes9/scripts/000_full_script.sql` (1,076 lines) and
`AI/supabase/migrations/000_full_script.sql` (1,026 lines) differ on 58 lines with an
identical table inventory, so the divergence is in columns, RLS, grants and functions —
exactly the surface ADR-012 makes authoritative. Choosing the authoritative baseline is an
operator decision and a precondition for wave 3.

**Notes9 has no CI.** `.github/` does not exist, so every fail-closed Law 2 guard in the
Data Analysis path is enforced by tests that nothing runs automatically. Wave 1 creates it;
until then, no assertion in this document about "CI fails on mismatch" is true for Notes9.

## Waves

Capped at 4 slices per wave, per `CLAUDE.md`.

**Wave 1 — make disagreement visible.** Notes9 CI created. `contracts/v1` package authored
from current behaviour with the smaller cap winning. `CONTRACT_HASH` parity test in both
repos. Gateway `temperature` default inverted to 0.0 and `BIOMNI_TEMPERATURE` given a code
default. No behaviour change beyond the temperature defaults; this wave exists so that
every later wave has a tripwire.

**Wave 2 — one client, one envelope.** Seam client in Notes9 supporting JSON and SSE, so no
route hand-rolls `fetch`. `outcome` discriminant added to every response branch. Allowlist
proxy replaced by schema-validated passthrough. Contract version negotiation.

**Wave 3 — close the invisible seam.** `AuthorizedReader` extracted as the sole holder of
service credentials, `scope_predicate` as the single scope rule, RLS-parity conformance
test across the four-role matrix. This wave is gated on the schema-baseline decision above.

**Wave 4 — Law 2 everywhere.** Fact ledger, producer minting, composer substitution,
default-deny lifted from `spec-author.ts` and applied to the main agent and citations.
Thread identity and bounded history. This wave is last because it depends on the envelope
from wave 2 carrying `facts` and `thread`.
