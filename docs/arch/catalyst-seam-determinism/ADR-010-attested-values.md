# ADR-010: Mint every user-visible fact deterministically; the model references, never types

- Status: accepted
- Date: 2026-08-15
- Feature: [[projects/catalyst-seam-determinism]]
- Supersedes: none

## Context

The product holds two rules that appear to conflict. Law 2 says no number reaches the user
that did not come from deterministic code. Conversational continuity requires the model to
see computed results so a follow-up means something. The moment the model can see a result
it can quote a number, and today's guard responds by deleting every numeric literal it did
not authorise.

The codebase already names this ceiling itself. `lib/data-analysis/ai/spec-author.ts:423-431`
records that integer statistics below 100 slip through the default-deny check, and states
the fix as threading the engine result in so numbers can be **attributed** rather than
guessed at.

It also already contains the mechanism, twice, generalised zero times. Citation tokens are
minted by deterministic code at tool-emit time and the model can only copy them
(`AI/catalyst/core/citations.py:32-39`) — the one structural guard on an otherwise entirely
fail-open path. And `MUTATION_CONTRACT` is generated by walking the validator
(`lib/data-analysis/spec/mutation-schema.ts:216`), so prompt and validator cannot drift.

The asymmetry this fixes: Data Analysis is fail-closed because its schema has no field that
can carry a statistic. Every other surface is fail-open because it inspects free text after
the fact. There is no code path anywhere that refuses to show a main-agent answer because a
number in it is unattributable.

## Decision

Every deterministic producer mints a `Fact` for each value it intends the user to see, into
a per-turn ledger, carrying `{token, rendered, value, unit?, producer, producer_version,
source_ref}`. The model receives the ledger as context and writes prose containing tokens.
A deterministic composer substitutes `token → rendered` as the final step before display.
A numeric literal outside a token is denied by default, with the three exemptions already
implemented at `spec-author.ts:392-404` (a digit welded to letters, a bare integer below
100, a four-digit year). A token with no ledger entry removes its sentence and discloses
the removal.

## Consequences

Attribution and prohibition stop being alternatives and become one mechanism: the model
never types a digit, so quoting is safe by construction and fabricating is structurally
impossible rather than caught by an inspector. The guard becomes fail-closed on every
surface, matching Data Analysis rather than the fail-open retrofit everywhere else.

It costs a real refactor of the citation composer and the main agent's answer path, and it
adds a ledger to every turn's payload. Prose becomes slightly harder to read in logs, since
raw model output contains tokens rather than numbers.

It forecloses free-form model prose containing computed values, permanently and
deliberately. A surface that genuinely needs that is a surface that cannot be published
from, and it must say so in the UI.

## Alternatives rejected

**Keep post-hoc inspection and widen the regex.** Rejected on the codebase's own evidence:
`app/api/data-analysis/spec-author/route.ts:365-377` documents a removed over-broad gate
that ran on typed mutation payloads and was "worse on both axes than no gate at all". An
enumerated-phrase detector can only ever catch what it enumerates.

**Forbid the model from seeing results at all.** Preserves Law 2 and destroys continuity,
which is half the user's ask. It also does not work: the model can still fabricate, it just
fabricates less plausibly.

**Trust the model with numbers and label the output.** This is the current fail-open state.
It has already produced a figure legend asserting `"Two-way ANOVA, p = n/a."` for a test
that never ran, in the one artifact explicitly built to be pasted into a paper.
